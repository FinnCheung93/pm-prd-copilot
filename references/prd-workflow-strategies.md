# 新写、修改、增量与评审策略

根据用户意图、材料和项目约定判断本次工作，能可靠判断时直接推进，不要求用户重新选择作业类型。

## 新写 PRD

从问题、目标、对象和范围理解需求，判断本轮需要讨论、粗稿还是可交付文档。信息充分且用户要求成文时直接写；用户只想讨论时，不替其完成尚未要求的整份 PRD。

原始材料中的用户反馈、方案设想和会议意见需要分析后使用。新功能也可能依赖已有能力，查明影响本期判断的现状即可，不要求追溯无关历史。

组织方式见正文组织参考；粗稿可承载已确定部分和明确标记的未定事项，不把缺少依据的内容补成确定规则。

## 修改已有 PRD

确认本次是局部修正、继续细化、重写还是写下一版；用户已说明或上下文清楚时无需再问。先找到本次变化，检查相关旧表述、状态、图示、数据定义和关联引用，处理必要联动。

保持未受影响内容稳定，不为套新结构重写整篇。被替代规则需要更新或移除，确保当前定义一致；历史修订记录按修订规范保留，不与正文旧规则混同。

局部修改不必重写开头概述；仅在整体目标或范围受到影响时同步。保护范围及新授权按主文件的修改边界执行。

## 独立增量 PRD

当旧文档代表已上线版本、本期变化相对独立，或直接改旧文会混淆版本时，可用独立文档承载本期需求。遵循用户要求和项目版本管理约定，不机械新建。

读取旧 PRD、全局规格和必要资料，理解本期目标、相关现状、变化及依赖。旧规则以链接或简短引用为准，正文聚焦本期变化，以及有关的兼容、迁移或生效条件。

默认不改旧 PRD 正文。若需要更新索引或全局规格，按实际影响和授权范围处理，不把历史规则复制成第二份权威定义。

## 评审 PRD

评审请求本身不代表获准改写。用户只要评审结论时，直接报告有依据的问题与建议，可以批量列出，不为固定流程先访谈。

评审服务后续修改时，能判断的问题先判断；需要补充且影响修改方向的信息，按主文件的澄清方式与用户讨论。获得修改授权后处理对应内容。

检查需求行为、规则与界面说明的一致性，也指出重复、可合并或可以移出正文的内容。建议深度与需求成熟度相称，不把粗稿按完整交付标准要求补满细节。
