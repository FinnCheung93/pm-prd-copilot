# 修订记录规范

每份 PRD 按一次提交到仓库维护一条对应修订记录，保留此前提交的历史条目。记录最终变更结果，不记录每轮对话或每次保存。

## 连续编辑与提交

同一次提交前的连续编辑合并维护当前条目，跨天不自动拆分。相对于上一提交总结最终有效变化，移除已撤回或被后续修改覆盖的中间变化；没有有效变化时不为过程增加记录。

优先从相关仓库历史、工作区差异和上下文确认提交边界，不只看日期。已提交的历史条目不自动合并；用户明确要求合并时按其范围处理。下一次提交新增一条。

无法可靠判断哪条属于本次待提交修改，且可能改到历史时，再请用户确认。没有仓库历史时不要猜测提交状态。

## 条目内容

多项变更在同一条内换行分点，每点写清修改位置与结果，避免只写“优化”“调整”等泛词。尽量链接到对应章节，复用项目支持的标题链接或稳定锚点，并检查跳转目标存在。具体列、版本号及换行方式沿用项目约定；Markdown 表格可用 <br> 换行。

使用可靠当前日期；已知实际提交日期时按实际情况填写。尚未提交的记录作为当前待提交条目维护，提交前校准日期，不预称已经提交，也不沿用无关旧日期。

只记本次 PRD 的最终变化，不写讨论过程或无关工程细节。章节重排时可概括主要结构变化，并更新受影响的链接。

维护修订记录不代表获得 Git commit、push 或合并的授权；提交行为按用户要求和项目约定执行。
